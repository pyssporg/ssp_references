# IMP-008: Verification Documentation Layer (KM-005)

**ID:** IMP-008
**Status:** proposed
**Theme:** Documentation Layer Separation — Verification Layer (KM-005)

**Evidence:**
- KM-005 defines a **Verification** layer between Implementation and the completion gate, but no `docs/05-verification/` directory exists.
- The test strategy document (`docs/04-implementation/co_simulation_test_strategy.md`) and fixture mapping document (`docs/04-implementation/co_simulation_fixture_mapping.md`) are verification artifacts — they describe *how to verify* engine behavior, not *how to implement* the build/simulate/compare pipeline.
- These documents currently live under `04-implementation/`, mixing the Implementation and Verification layers per KM-005's chain.
- The FIXTURE-template.md references the test strategy (verification concern) in its "Strategy Role" section, which is correct cross-layer referencing but the source document is in the wrong layer directory.
- The architecture doc (`02-system-architecture/architecture.md`) does not reference the test strategy, which is correct per KM-005 (architecture should not link down to verification). But the test strategy's current location under `04-implementation/` makes it harder to find as a verification artifact.

**Current pain or risk:**
1. KM-005's Verification layer is empty, making the documentation chain incomplete.
2. Verification artifacts (test strategy, fixture mapping) are co-located with implementation artifacts (FIXTURE-template.md, workflow docs), making it harder to distinguish "how we build" from "how we verify."
3. Future contributors looking for verification/acceptance criteria may not find the test strategy under `04-implementation/`.
4. KM-005 reviews cannot verify the Verification layer exists.

**Proposed improvement:**
1. Create `docs/05-verification/` directory.
2. Move `docs/04-implementation/co_simulation_test_strategy.md` to `docs/05-verification/co_simulation_test_strategy.md`.
3. Move `docs/04-implementation/co_simulation_fixture_mapping.md` to `docs/05-verification/co_simulation_fixture_mapping.md`.
4. Update cross-references in:
   - `docs/04-implementation/ls_ref_ssp_experiment_workflow.md` (references test strategy)
   - `docs/04-implementation/FIXTURE-template.md` (references test strategy)
   - `docs/05-verification/co_simulation_fixture_mapping.md` (references test strategy — self-referencing after move)
5. Add a `docs/05-verification/README.md` explaining the Verification layer and linking to the test strategy and fixture mapping documents.
6. Do **not** modify content of any moved document — only update cross-reference paths.

**Expected benefit:**
- KM-005's Verification layer becomes populated with two existing artifacts.
- Implementation (`04-implementation/`) contains only build/setup/workflow documentation.
- Verification artifacts are findable in a dedicated location.
- The documentation chain becomes complete: Intent → Product Decisions → System Architecture → Technical Decisions → Implementation → Verification.

**Risk and blast radius:**
- **Risk:** Low. File moves only if cross-references are updated completely. Medium if stale references are left behind (KM-007 risk).
- **Risk of broken links:** Every in-repo reference to the old paths must be updated. The `ls_ref_ssp_experiment_workflow.md` and `FIXTURE-template.md` are the known references; a grep for `co_simulation_test_strategy` and `co_simulation_fixture_mapping` across the entire repo is required.
- **Blast radius:** 2 files moved, 1 new README, 2-3 cross-reference updates. No code changes, no ADR changes, no architecture doc changes.

**Prerequisites:** None (independent of IMP-006 and IMP-007).

**Suggested priority:** Medium — fills the last missing layer in KM-005's chain but does not affect any decision-recording or architecture documentation.
