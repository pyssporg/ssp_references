# IMP-006: Product Decisions Layer (KM-005)

**ID:** IMP-006
**Status:** proposed
**Theme:** Documentation Layer Separation — Product Decisions Layer (KM-005)

**Evidence:**
- KM-005 defines a dedicated **Product Decisions** layer between Intent and System Architecture that should "translate intent into durable product promises," but no separate artifact exists for this layer.
- The current `docs/00-intent/intent.md` has a "Product Commitments" section that partially serves this role, but these are stated commitments without decision rationale — they do not record *why* each commitment was chosen or what alternatives were considered.
- Design decision **DD-2 ("Comparison Is Engine-to-Engine Only")** in `docs/03-technical-decisions/design-decisions-log.md` is a product-level scope decision (what the repository promises about comparison methodology), not a technical implementation choice. It sits in the Technical Decisions layer per the `03-technical-decisions/` convention, misaligned with KM-005.
- Design decision **DD-6 ("Simulation Registry Is the Single Source of Truth")** straddles the product/technical boundary: the *decision* to treat the registry as exclusive source of truth is a product commitment, while the *implementation details* (JSON schema, file path) are technical.
- No other product-level decisions are recorded anywhere — e.g., "which backends do we support and why?", "which fixture classes do we commit to maintaining?", "what tolerance philosophy do we adopt?" These are product decisions, not technical ones.

**Current pain or risk:**
Without a distinct Product Decisions layer:
1. Future contributors cannot distinguish "what did we decide to promise?" (product) from "how did we implement it?" (technical).
2. Product-level decisions like engine-to-engine comparison are buried in a technical decisions document, making them harder to find during product-scope discussions.
3. The Chain of intent → promise → architecture → build is incomplete: Intent states purpose, but the translation from purpose into durable promises has no recorded rationale.
4. KM-005 reviews cannot verify "product commitments/decisions translate intent into durable product promises" because no dedicated Product Decisions artifact exists.

**Proposed improvement:**
1. Create a Product Decisions artifact at `docs/01-product-decisions/product-decisions.md` that records the repository's product-level decisions with context, alternatives considered, rationale, and consequences — matching the ADR template structure but at the Product Decisions layer.
2. Migrate DD-2 ("Comparison Is Engine-to-Engine Only") from `design-decisions-log.md` into the new product decisions artifact. Replace the DD-2 entry with a cross-reference note pointing to the new artifact.
3. Evaluate DD-6 ("Simulation Registry Is the Single Source of Truth") — if it has a product-decision character, migrate or mirror it to the product decisions artifact as well.
4. Add missing product-level decisions that are implicitly settled but never recorded (e.g., supported backends, fixture class scope, comparison tolerance philosophy).
5. Update `docs/00-intent/intent.md` to link forward to the Product Decisions artifact rather than trying to serve both roles.
6. Update the `docs/` README or directory index to reflect the `01-product-decisions/` layer.

**Expected benefit:**
- KM-005's Product Decisions layer becomes explicitly populated.
- Product-level decisions are findable in a dedicated location with rationale.
- The Intent document stays focused on purpose and commitments (not decision rationale).
- Technical Decisions (`03-technical-decisions/`) can focus on bridging architecture to build details without product-level content.
- KM-005 reviews gain a concrete artifact to check against.

**Risk and blast radius:**
- **Risk:** Low-Medium. Creates a new directory and artifact. Requires moving one existing design decision and updating its cross-references. May require adding 2-3 new decision entries for decisions that are settled but implicit.
- **Risk of scope creep:** Must resist the temptation to also re-architect `intent.md` or `architecture.md` within this ticket. The improvement is focused on adding the missing layer, not rewriting existing layers.
- **Risk of duplication:** Must not duplicate content from `intent.md` (Product Commitments). The product decisions artifact records *why* decisions were made, not what is promised. The intent document records *what* is promised/not-goaled.
- **Blast radius:** New directory `docs/01-product-decisions/`, new file `product-decisions.md`, edit to `docs/03-technical-decisions/design-decisions-log.md` (reclassify DD-2), edit to `docs/00-intent/intent.md` (link forward). No code changes.

**Prerequisites:** None (independent of IMP-007 and IMP-008).

**Suggested priority:** High — fills a missing layer in KM-005's documentation chain.

Seed it with at least 3 entries: (a) "Comparison Methodology: Engine-to-Engine Only" (migrated from DD-2), (b) "Simulation Registry Is the Source of Truth" (migrated or mirrored from DD-6), (c) "Supported Backends" (capture the current implicit scope — OMSimulator and ssp4sim). Do not modify any architecture, implementation, or code files.
