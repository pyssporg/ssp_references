# scenario — pinned FMU body and source

## Provenance

`models/fmu/scenario/fmu` is the pinned FMU body consumed by the `scenario` SSP
fixture. Its `modelDescription.xml` was generated by the legacy
`scenario_fmu` 0.1.0 (`author` and `generationTool` are `scenario_fmu`,
`version` is `0.1.0`) and it carries the linux64 `scenario.so` binary.

The build source is now `pyfmu_scenario` v0.1.0, which regenerates the same FMI
2.0 interface from `scenario.txt`. That file holds the pinned body's default
`scenario_input` text: five series (`Alt`, `Mach`, `heat_load`, `Wgt_On_Whl`,
`Aircraft_state`) with the exact names, interpolation modes, times, and values
from the checked-in `modelDescription.xml`.

The embedding system, the model-owned parameter set, the experiment, and the
expected runtime behavior live in `models/ssp/scenario/FIXTURE.md`; this note
covers only the FMU side.

## Architecture Source

- `architecture/Scenario.sysml` declares the FMU-side interface:
  `ScenarioParameters :> ParameterInterface` (the String `scenario_input`),
  `RealSignal`, `ScenarioFmu :> FmuMetadata`, and
  `part def Scenario :> FmuModel` with the five Real outputs. It uses the same
  package and definition names as
  `models/ssp/scenario/architecture/scenario.sysml`, so the two views describe
  one interface.
- The directory exists so `scripts/build_models.py` discovers the model: an FMU
  build script counts only next to an `architecture/` directory.
- The producer, not `pyfmi_sysml`, emits the body. The architecture is the
  declaration of what the producer must emit, and the check in `build.py` is
  what holds the two together. `ScenarioFmu.source` names the built archive at
  `artifacts/build/scenario/scenario.fmu`.
- No definition, description, or binary under `fmu/` is hand-edited; the pinned
  body changes only through `--refresh`.

## Build contract

```bash
python3 scripts/build_models.py run scenario
```

The wrapper runs this FMU build first, then `models/ssp/scenario/build.py`. The
interpreter must be able to import `pyfmu_scenario` beside the repository's
runtime stack: install the sibling `repos/pyfmu_scenario` checkout editable, or
put its `src/` on `PYTHONPATH`. The build script:

1. parses `scenario.txt` into the typed series model;
2. packages an FMI 2.0 CoSimulation archive at
   `artifacts/build/scenario/scenario.fmu` with
   `pyfmu_scenario.packaging.package_scenario` and the fixture GUID;
3. compares the built interface against `fmu/modelDescription.xml`:
   `modelName`/`modelIdentifier` `scenario`, `fmiVersion` 2.0, the same GUID,
   the six variables in order (names, causalities, variabilities, types, value
   references, and the `scenario_input` start text), and the same
   `ModelStructure/Outputs`;
4. simulates the pinned body and the built archive with FMPy and compares the
   five output trajectories; when FMPy is not installed the check prints a skip
   reason instead of failing;
5. prints what it produced and verified, and exits nonzero on any mismatch.

The default run never writes into `fmu/`; it is verify-only.

### Refresh

`models/fmu/scenario/build.py --refresh` additionally extracts
`modelDescription.xml` and `binaries/linux64/scenario.so` from the new archive
into `models/fmu/scenario/fmu/`. Refresh happens only after the interface check
passes; a mismatch leaves the pinned body untouched.

```bash
PYTHONPATH=../pyfmu_scenario/src \
  ../pyfmi_interfaces/.venv/bin/python models/fmu/scenario/build.py --refresh
```

## Determinism and identity

- `modelName` and `modelIdentifier` are `scenario`; the GUID stays
  `9524b75e-dc71-47cd-a02f-e22b95a3f76d`.
- `author`, `generationTool`, and `generationDateAndTime` are deliberately not
  compared: the producer identifies itself as `pyssporg` / `pyfmu-scenario` and
  emits no generation time. Those fields change when the body is refreshed; the
  GUID and the FMI interface do not.
- The archive is deterministic, but it is not byte-comparable to the legacy
  pinned binary. Interface equality and trajectory equality are the contract.
- Recorded verification with `pyfmu_scenario 0.1.0` and FMPy 0.3.32: 501
  samples, maximum absolute output difference `0` against the pinned body.

## Relationship to the SSP fixture and ssp4sim

`models/ssp/scenario` embeds this body through
`ScenarioFmu.source = "models/fmu/scenario/fmu"`; rebuilding the FMU changes
the SSP's embedded archive on its next build. The `ssp4sim` checkout vendors a
snapshot of this repository at `repos/ssp4sim/resources/reference_ssp`; that
snapshot is refreshed separately and is not edited from here.
