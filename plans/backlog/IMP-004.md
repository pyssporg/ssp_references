# IMP-004: FIXTURE.md Canonical Template and Standardization

**ID:** IMP-004
**Status:** proposed
**Theme:** Fixture Documentation Consistency — Implementation Layer (KM-005)

**Evidence:**
- All 15 FIXTURE.md files share a similar structure but with meaningful variations:
  - Simple reference models (BouncingBall, Dahlquist, VanDerPol, Resource, Stair): 5 sections — Origin, Overview, Strategy Role, Main Risks Covered, Typical Use.
  - Signal-propagation models (signal_step_gain, signal_step_add, signal_fanout_gain, signal_sine_gain_add, signal_step_product, signal_delay_detector): 8 sections — Origin, Overview, Structure, Strategy Role, Intent, Expected Behavior, Main Failures Catches, Typical Use.
  - Composite models (dcmotor, embrace): 5 sections plus optional notes (OMSimulator Notes for embrace).
  - Outliers: `scenario/FIXTURE.md` (sparse, different structure — L3-22, no proper "Origin"Origin" section). `pyfmu_csv_source_sink/FIXTURE.md` (unique sections: Inputs, Simulation Notes).
- Strategy Role values are not consistently formatted — some use bullet lists, some use single lines, some use descriptive text.
- No canonical template definition exists in the repository.
- KM-004 (minimize parallel structures) applies to documentation as well as code — inconsistent FIXTURE.md structures are a form of parallel structure.

**Current pain or risk:**
Inconsistent FIXTURE.md sections make it harder to scan and compare fixtures at a glance. Agents generating new FIXTURE.md files have no template to follow, risking further divergence. The `scenario` and `pyfmu_csv_source_sink` fixtures are notably divergent, suggesting ad hoc authoring without a shared convention.

**Proposed improvement:**
1. Define a canonical FIXTURE.md template with required sections (Origin, Overview, Strategy Role) and optional sections (Structure, Intent, Expected Behavior, Main Failures Caught, Simulation Notes, Packaging Notes).
2. Store the template as `.opencode/templates/fixtures/FIXTURE-template.md`.
3. Reformat the outlying FIXTURE.md files (`scenario`, `pyfmu_csv_source_sink`) to align with the template, preserving all existing content.
4. Add a documentation guideline note about the FIXTURE.md template.

**Expected benefit:**
- All 15 FIXTURE.md files follow a consistent structure.
- Agents creating new fixtures have a canonical template to follow.
- Scanning and comparing fixture metadata becomes predictable.
- Reduces the "divergence within the implementation" that the pain point describes.

**Risk and blast radius:**
- **Risk:** Low-medium. Touches 2-3 FIXTURE.md files for reformatting; no content change, only section reordering/renaming. The template definition is a new file.
- **Risk of content loss:** Migration must preserve all existing text, Observer pattern, and fixture-specific notes. No information should be removed.
- **Blast radius:** 1 new template file, 2-3 FIXTURE.md edits, 1 update to AGENTS.md documentation guidelines. No code changes.

**Suggested priority:** Medium (lower than IMP-001/IMP-002 but can proceed independently)

**Task contract seed:**
(1) Create `.opencode/templates/fixtures/FIXTURE-template.md` with sections: **Required** — Origin, Overview, Strategy Role; **Optional** — Structure, Intent, Expected Behavior, Main Failures Caught, Simulation Notes, Packaging Notes, Engine-Specific Notes. Include inline comments explaining what each section should contain. (2) Reformat `models/ssp/scenario/FIXTURE.md` to use the template's required sections, preserving all existing content. (3) Reformat `models/ssp/pyfmu_csv_source_sink/FIXTURE.md` similarly. (4) Update AGENTS.md documentation guidelines to reference the FIXTURE template. Do not modify content of other FIXTURE.md files. Do not modify any code, build scripts, or configuration files.

**Notes:** This is a documentation-consistency improvement, not an architecture or traceability change. It can be done independently of IMP-001/IMP-002/IMP-003. The template should be flexible enough to accommodate fixture-specific notes (like `embrace`'s OMSimulator notes) as optional sections.
