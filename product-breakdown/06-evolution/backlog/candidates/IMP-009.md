# IMP-009: Fixture — Flat Inline SSV with External SSM Mapping

## Status

Proposed

## Layer

Implementation (03-implementation) — new fixture in `models/ssp/`

## Theme

SSP parameter binding coverage — flat inline SSV values combined with an
external SSM mapping file

## Evidence

- `product-breakdown/04-verification/co_simulation_fixture_mapping.md`
  documents packaging alternatives for signal-propagation fixtures.
- No existing fixture combines inline `<ssd:ParameterValues>` with an external
  `<ssd:ParameterMapping source="...">`.
- `signal_sine_gain_add` uses inline system-level parameters via
  `ssd.extend_system_parameterset()` with dotted names (no mapping needed).
- `signal_step_add` uses external SSV with flat names + external SSM.
- `signal_step_gain` uses external SSV with dotted names (no mapping).

## Current Pain Or Risk

The SSP standard allows `<ssd:ParameterBinding>` to contain both
`<ssd:ParameterValues>` (inline) and `<ssd:ParameterMapping>` (external).
No fixture tests this combination, so engine support for resolving inline
parameter values through an external mapping file is not validated. An engine
could silently ignore the mapping when values are inline, or fail to apply
it, and no regression test would catch it.

## Proposed Improvement

Create a new fixture `signal_parameter_inline_with_mapping` in
`models/ssp/`:

- Single Step component with 3 parameters (`step_height`, `step_offset`,
  `step_startTime`).
- Inline SSV: parameter values embedded in `<ssd:ParameterValues>` inside
  the SSD (no `source=` attribute).
- External SSM: `<ssd:ParameterMapping source="resources/..._mapping.ssm">`
  mapping flat names (`step_height`) to dotted component paths
  (`step.height`).
- Self-connection: `step.y → step.y` (or output connector per convention).
- Distinct values: height=1.0, offset=0.0, startTime=0.25.
- Build approach: generated SSD (via `build.py` using pyssp_standard) or
  checked-in SSD — whichever fits the inline+external pattern cleanly.

## Expected Benefit

- Closes a gap in SSP standard compliance coverage.
- Validates that engines correctly apply external parameter mappings to
  inline parameter values.
- Provides a minimal reproducer for mapping-resolution bugs that only
  surface when values are inline but names need translation.

## Risk And Blast Radius

Low. New fixture directory under `models/ssp/`. No existing fixtures,
build scripts, or checked-in files are modified. Follows the established
fixture convention.
