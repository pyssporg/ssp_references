# IMP-015: Backend Adapter Integration Tests

## Status

Proposed

## Layer

Verification (04-verification) — new test functions

## Theme

Unit and integration tests for the backend adapter functions that verify config
generation, runtime setup, and result CSV contract conformance.

## Evidence

- `backend_adapter_review.md` (IMP-CAND-H) documents backend adapter contracts
  and found gaps: OMSimulator tolerance not set, no config.json for OMSimulator,
  adapter code not in separate files as documented.
- No test calls `simulate_ssp4sim()`, `simulate_omsimulator()`, or
  `simulate_fmpy()` to verify they produce the expected artifacts.
- The adapter functions are the most complex parts of the pipeline
  (multiprocessing, temp directories, FMU repacking, MAT-to-CSV conversion)
  but have zero test coverage.
- The `_ssp4sim_config_payload()` function produces a complex config dictionary
  that has no schema validation.

## Current Pain Or Risk

- Adapter refactoring has no regression safety net.
- Config generation errors (wrong field name, missing key) go undetected until
  runtime.
- The adapter-agnostic `unpack_mat_to_csv()` function has no test coverage for
  real MAT files.
- The FMPy connection resolver (`_fmpy_get_connections()`) is a workaround
  that has no dedicated tests.

## Proposed Improvement

1. **Test `_ssp4sim_config_payload()`**: verify that the config dict contains
   all expected keys with correct types for a known setup.

2. **Test `_fmpy_get_connections()`**: create a minimal SSP structure and verify
   connections are resolved correctly.

3. **Test MAT-to-CSV conversion** (`unpack_mat_to_csv()`, `extract_series()`):
   create a minimal synthetic MAT file or use a real one from the repository,
   and verify signal extraction produces correct headers and values.

4. **Test `simulate_backend()` dispatch**: verify that the routing function
   returns the correct adapter for each backend name (mock the adapter to avoid
   real simulation).

## Expected Benefit

- Catches config generation errors before simulation runs.
- Provides regression safety net for the most complex pipeline code.
- Validates the MAT-to-CSV conversion that OMSimulator results depend on.
- Guards the FMPy workaround against regressions.

## Risk And Blast Radius

Low. New test functions only. Tests that need real simulation engines should
be conditionally skipped.

## Suggested Priority

Medium

## Task Contract Seed

1. Write `test_ssp4sim_config_payload()`:
   - Create a `SimulationSetup` with known values.
   - Call `_ssp4sim_config_payload()` and verify all expected keys exist
     with correct types and values.

2. Write `test_fmpy_connections()`:
   - Create a minimal in-memory SSP structure.
   - Call `_fmpy_get_connections()` and verify connection resolution.

3. Write `test_unpack_mat_to_csv()`:
   - Create a minimal synthetic MAT file with known signal layout.
   - Call `unpack_mat_to_csv()` and verify CSV output matches expectations.

4. Write `test_simulate_backend_dispatch()`:
   - Verify `simulate_backend()` routes to the correct adapter function for
     each backend name.
   - Verify unknown backend raises `NotImplementedError`.

5. Mark tests requiring real MAT files or simulation engines with
   `pytest.mark.skipif`.

## Out Of Scope

- Running actual simulations (these test the adapter functions, not the engines).
- Changes to the adapter implementation (tests only verify current behavior).
- Integration with external simulation packages (use mock/synthetic data).

## Traceability

- Verification: `backend_adapter_review.md` (IMP-CAND-H).
- Implementation: `scripts/workflow/simulate.py`.
- Tests: New functions in `tests/test_workflow.py` or a new file.
