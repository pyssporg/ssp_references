# IMP-010: Fixture — Nested System with External SSV+SSM Bindings

## Status

Proposed

## Layer

Implementation (03-implementation) — new fixture in `models/ssp/`

## Theme

SSP parameter binding coverage — external SSV+SSM files referenced from
inside a nested `<System>` element

## Evidence

- `product-breakdown/04-verification/co_simulation_fixture_mapping.md`
  documents packaging alternatives but omits nested-system packaging.
- `signal_nested_parameter_bindings` has external root SSV+SSM but uses
  inline `<ssd:ParameterValues>` inside the nested system.
- No fixture references external `.ssv` and `.ssm` files from a
  `<ssd:ParameterBinding>` element inside a nested `<System>`.
- The SSP standard allows parameter sources at any hierarchy level — a
  nested system can independently reference its own external parameter
  files.

## Current Pain Or Risk

Parameter resolution across hierarchy levels is a common source of engine
incompatibility. Without a fixture that places external SSV+SSM bindings
inside a nested system, engine bugs in nested parameter resolution (e.g.,
failing to resolve relative paths, using wrong base directory, or skipping
nested-system parameter bindings) go undetected in the regression suite.

## Proposed Improvement

Create a new fixture `signal_nested_external_bindings` in `models/ssp/`:

- Root system with a Step component (inline SSV: height=1.0, offset=0.0,
  startTime=0.25).
- Nested `<System name="inner">` containing a Sine component.
- Nested system parameters via external files:
  - `resources/inner_parameters.ssv` with flat names (`sine_amplitude`,
    `sine_f`, `sine_offset`).
  - `resources/inner_mapping.ssm` mapping flat names to dotted
    (`sine.amplitude`, `sine.f`, `sine.offset`).
- Distinct values: amplitude=2.0, f=5.0, offset=0.5 (all differ from
  FMU defaults so test values confirm external file sourcing).
- Real signal routing: `sine.y → inner.y` and `step.y → system.y`.
- Build approach: checked-in `SystemStructure.ssd` (like
  `signal_nested_parameter_bindings`) so that SSV/SSM files are versioned.

## Expected Benefit

- Closes a gap in SSP standard compliance coverage for nested parameter
  resolution.
- Validates that engines correctly resolve relative paths for external
  parameter files inside nested systems.
- Provides a regression test for DFS traversal and hierarchy-aware
  parameter collection in engines.

## Risk And Blast Radius

Low. New fixture directory under `models/ssp/`. No existing fixtures,
build scripts, or checked-in files are modified. Follows the established
fixture convention.
